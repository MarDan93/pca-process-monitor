## Implemented and verified

- `MOULD_RUNTIME=hosted` fails closed without an exact HTTPS origin, owner password, session secret and absolute persistent database path. A single-owner login protects project/asset/operation APIs; local developer mode remains loopback-only.
- Server-side sessions and hashed opaque tokens persist in SQLite. Secure/HttpOnly/SameSite cookies, exact origin checks, session-derived CSRF tokens, rate/concurrency limits and generic login errors are enforced. Expiry, logout and password/secret rotation revoke sessions. No password is stored in source, frontend bundles or snapshots.
- A browser sign-in screen and sign-out control are integrated with the same CAD workspace. Hosted status says online/server storage. Project import/revision/approval/undo and actual browser AI are the existing application features, not replaced by a static mock or IndexedDB demo.
- The digest-pinned multi-stage Docker image builds successfully. Python requirements install with official SHA-256 locks; npm lifecycle scripts remain disabled. Only the compiled browser runtime and Python service are in the final image; model weights, local data, node_modules, virtual environments and proxy CA files are excluded. Runtime licence texts are retained.
- The container initialises only `/var/data` and drops to UID/GID 10001 before handling requests. An initial container check found unreadable root-owned source modes; the Docker recipe now explicitly sets public read/traverse permissions while retaining root ownership. The corrected image passes the actual startup test.
- The actual image runs within **512 MiB / 0.5 CPU**, protects anonymous data access, accepts real sign-in/CSRF, saves an approved commercial update and original OBJ bytes with declared units. After deleting and replacing the container on the same persistent volume, the authenticated session, project, revisions and original file remain available. Logout invalidates the cookie. The test cleans its own container/volume.
