## Environment limitations and coverage boundaries

Default remote browser downloads failed with `net::ERR_CERT_AUTHORITY_INVALID` in this managed Chromium instance. The legacy NSS trust database overrides the isolated test database; permission to update it was not granted. It was not modified. System-trusted HTTPS downloads of the model and npm runtime assets succeed. Same-origin hosting is a supported deployment setting and passes actual inference; it does not disable certificate checks or substitute model responses.

Direct `file://` navigation is blocked by the cloud browser policy, so the standalone HTML was tested over an internal HTTP server. Model/runtime weights are not in the ZIP. First AI use needs about 800 MB of downloads, browser memory and CPU time. No public hosted application is deployed by this increment.

Early prompt trials returned malformed JSON and invented fields; the strict update contract rejected them. The final UI provides plain conversation separately from structured change proposals. This improves the tested flow but does not establish extraction accuracy for arbitrary requests, languages, geometries or repeated sessions. All AI proposals require review. Mould design, STEP solids, cooling, press/robot cycle simulation, costs and engineering qualification remain outside this demo.

Machine-readable run artefacts are under ignored `.cache/ai` and `.cache/ux`; model weights remain outside Git. The distributable ZIP and screenshot are generated after the final standalone core check.
